# macOS 客户端验证记录（2026-10-18）

## 本轮修复

- 原生设置文件成为 Gateway 地址、API Key 和快捷键的唯一启动来源。设置写入串行化，写入失败会返回错误；快捷键注册失败时恢复旧绑定。
- 预热请求合并并去重；失败后可以重试。连接测试设有超时，并区分无效 Key、断网和超时。
- 删除浏览器录音后上传 WAV 到 `/v1/transcribe` 的旧入口。正式听写使用原生麦克风、Opus 和 `/v1/dictation/stream`。
- 录音失败时在胶囊显示错误，并尝试打开设置页。识别成功后始终说明文字已复制到剪贴板；找不到原输入窗口时提示手动粘贴。

## 验证结果

| 场景 | 方法 | 结果 |
| --- | --- | --- |
| 前端构建 | `npm run build` | 通过 |
| Rust 编译检查 | `cargo check --locked --offline` | 通过；保留 9 条既有警告 |
| Gateway 失败路径与预热 | `npm run test:gateway` | 3 项通过：401、断网/超时、单次预热与失败重试 |
| 无效 Key（在线服务） | 用无效测试 Key 请求 `/v1/transcribe` | HTTP 401 |
| 断网（本机拒绝连接） | 请求 `127.0.0.1:9/health` | 连接失败 |
| Fn+F9 → 说话 → ✓ | 用户在 macOS 实测 | 转写文字进入剪贴板；微信草稿自动回填通过，文本编辑的早期测试未通过 |
| Fn+F9 → × | 用户在 macOS 实测 | 胶囊消失，文稿未写入 |
| 失败提示 | 用户在 macOS 实测 | 胶囊显示上游与麦克风权限错误；修复后辅助功能权限失效也会显示明确提示，剪贴板可手动粘贴 |
| 麦克风权限拒绝 | 用户在系统设置关闭麦克风权限后实测 | 胶囊显示权限错误；权限已重新打开，系统要求重启，客户端已重启 |
| 权限恢复与设置持久化 | 重启最终版后，用户再次完成 Fn+F9 → ✓ → ⌘V | 转写可粘贴，无权限错误；已保存的 Gateway 设置在重启后有效 |
| 微信“文件传输助手”自动回填 | 微信输入框 Fn+F9 → 说话 → ✓；未发送消息 | 通过：用户确认转写文字自动进入微信草稿。此前诊断确认目标 PID 是微信，但 macOS 辅助功能信任状态为 false；移除旧权限条目、添加当前构建的应用并重启后复测通过 |

## 当前限制

微信自动回填已通过一次最终版人工实测。此前重新构建后 macOS 辅助功能授权失效，阻止客户端切回录音前的微信窗口；遇到该情况需在系统设置中移除旧条目、添加当前应用并重启。文本编辑的自动回填尚未在重新授权后复测，Windows 桌面流程也未在本机验证。
