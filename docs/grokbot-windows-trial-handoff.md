# Grokbot：Typeless2api Windows 客户端试用对接文档

更新：2026-10-19 · 目标版本：`v2.0.1win`（Windows x64，应用版本 2.0.1）

## 目标与交付

请在 **Windows 实机或带有可用麦克风的 Windows 桌面会话** 中验证安装、Gateway 连接、F9 听写、自动回填和取消。交付一份逐项结果及失败证据。构建通过不等于实机听写通过；`v2.0.1win` 的实机结果目前待验证。

先用空白记事本测试。不要在聊天软件里发送消息，也不要在测试文稿中放入隐私内容。不要修改 Gateway 或上传 API Key、音频、包含密钥的截图。

## 配置

1. 启动 `typeless-client`。它常驻系统托盘；单击托盘图标打开设置页，右键菜单也有“打开设置…”和“退出”。
2. Gateway 地址填 `http://122.152.251.247`，**不要**使用默认的 `http://127.0.0.1:8787`，也不要添加 `:8787`。若负责人提供了更新的地址，以新地址为准。
3. API Key 由负责人单独提供。不要把 Key 写入这份文档、聊天记录、日志或截图。
4. 点击“测试连接”。预期显示“已连接”和“Gateway 可用，API Key 已验证”。
5. 听写快捷键设为 `F9`。若笔记本把 F9 作为硬件功能键，试 `Fn+F9`，或在设置页改成未被占用的快捷键。

当前测试地址使用明文 HTTP；试用时应使用专门的、可撤销的测试 Key，并限制在可信网络。客户端会在本地保存连接设置。

## 实机测试

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| T1 连接 | 按上述配置点击“测试连接” | 显示“已连接”，无认证或网络错误 |
| T2 听写 | 打开空白记事本并点击输入区；按 F9，连续清楚说“这是 Windows 客户端完整听写测试，请把这句话写进记事本”约 5 秒，点胶囊 ✓，等候结果 | 胶囊出现并进入处理状态；无错误；识别文字**自动出现在记事本** |
| T3 回填诊断 | 仅当 T2 没自动输入时，在记事本按 `Ctrl+V` | 若能粘贴出刚才的话，记录为“识别成功、自动回填失败”，不能算 T2 通过 |
| T4 取消 | 新起一行，F9 后说“这句应该取消”，点胶囊 × | 胶囊消失，记事本没有新增这句话 |
| T5 设置页按钮 | 点击托盘图标打开设置，点“开始听写”，随后点胶囊 × | 出现胶囊，取消后应用仍可使用 |
| T6 恢复 | 关闭并重新启动客户端，再打开设置页 | Gateway 地址和快捷键仍在；再次测试连接成功 |

请勿按记事本之外应用的“发送”按钮。若系统请求麦克风权限，请允许后重新执行 T2；可在“设置 → 系统 → 声音 → 输入”观察麦克风电平是否随说话跳动。

## 失败时如何定位

| 现象 | 优先检查与记录 |
| --- | --- |
| “无法连接 Gateway” | 先看地址是否仍是 `127.0.0.1`；再看网络和 Gateway 健康状态。不要发送 Key。 |
| “API Key 无效或已吊销” | 与负责人核对测试 Key；不要公开粘贴原文。 |
| F9 没有胶囊 | 看设置页实际快捷键、是否需要 Fn、是否与其他软件冲突；试设置页“开始听写”。 |
| 胶囊报 `Audio chunk too small to process` 或 `upstream_error` | 核对安装版本确实是 2.0.1；记录完整错误、录音时长、麦克风输入电平。2.0.1 已修复客户端末尾短音频块，但 Windows 实机仍需验证。 |
| 胶囊消失、记事本为空，但 `Ctrl+V` 有文字 | 转写已成功，问题在自动回填；记录目标应用、焦点是否在输入区、是否以管理员权限运行目标应用。 |
| 剪贴板也没有文字 | 记录完整错误以及声音输入电平；优先区分麦克风采集与上游转写错误。 |

Windows 上手动粘贴用 **`Ctrl+V`**。当前设置页某条成功提示可能显示 `⌘V`，那是界面文案问题，不能据此判断 Windows 回填已完成。

## 技术边界

客户端采集麦克风音频，在本机转成 16 kHz 单声道 PCM，每 1024 个采样编码一块 Ogg Opus；通过 WebSocket `/v1/dictation/stream` 发送给 Gateway。Gateway 返回 `refined_text` 后，客户端先写入剪贴板，再尝试切回开始听写时的窗口并模拟 Windows 粘贴。取消会停止会话，不写入文字。`v2.0.1win` 把末尾不足 1024 采样的一块补静音到标准长度。

此试用不需要在 Windows 上部署 Gateway，也不需要登录 Typeless。若要做协议级联调，再单独申请 Gateway 接口文档与测试 Key；此处以桌面端的用户流程为准。
